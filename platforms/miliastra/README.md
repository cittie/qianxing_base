> 本文件只写**平台事实**（能力 / 上限 / 约束 / 工具）。设计层的抽象见 `../../design/`；

## 3. 事件与生命周期（设计时最常踩的点）

- 事件是否生效**取决于挂载者**：例如**实体销毁 / 移除类事件只有在【关卡实体】的节点图上才会触发** ——
  挂到元件上会**静默失效**。这类"不报错但没反应"的坑，是本平台最贵的一类问题。
- 常见事件：实体创建时、定时器触发时、卡牌选择器完成时、实体销毁时……
- 查询类：查询自定义变量快照（**仅可用于实体销毁时**）等。

### 3.1 信号桥：客户端 → 服务器（跨端通信的标准做法）

**平台自带的跨端通信机制**，客户端想告诉服务器"发生了什么"时走这条：

| 环节 | 节点 / 接口 | 要点 |
| --- | --- | --- |
| 定义 | **信号管理器** | 信号需要先定义，并可带参数（字符串 / 实体列表 / 实体…都行） |
| 服务器发 | 【**发送信号**】 | 选中信号名后，**入参自动新增该信号的全部参数** |
| **客户端发** | 【**向服务器节点图发送信号**】 | 在**技能节点图**里用已定义的信号发送 —— **所有服务器节点图都能监听到该信号** |
| 任意实体收 | 【**监听信号**】（事件节点） | 先选信号名；出参自动新增该信号的全部参数；出参含**事件源实体 / 事件源GUID / 信号来源实体**（= 用【发送信号】发它的实体） |
| 客户端脚本 ↔ 服务器 | `ServerSignal:SendSignal()`（客户端脚本上行）、【发送客户端脚本信号】（服务器下行） | Lua 侧另有 `Register…` 回调 |

⭐ **实践含义**：**客户端拿到的东西（比如光标点中的实体）不可能直接给服务器图用** ——
必须经由信号桥把它当**信号参数**传过去。这也是"点击放置"这类交互的标准落地路径。
⚠️ 联机时服务器发信号**延迟最低约 100 ms**（官方说明），别把它当成每帧同步的手段。

> 📌 一份社区参考资产（第三方，本地学习用、不入库）用的就是这个骨架：
> 它自定义「鼠标点击时 / 被鼠标选中时 / 点击实体时」等信号 + 一个「鼠标检测体」，
> 用 **位置/实体列表查询 + 自定义信号** 把"点到了谁"（参数：被点击实体）送给业务图 ——
> 反过来说明**平台确实没有现成的"点击实体"事件**，需要自己搭。

### 3.2 调试设施（做任何实测前先开好）

| 设施 | 位置 | 作用 |
| --- | --- | --- |
| **节点图日志** | **窗口 → 日志** → 节点图日志页签 | 展示节点图在各时间点的**运行流程** + 各节点的**参数输入输出值** |
| **打印字符串**节点 | 执行节点 §一-1，入参只有「字符串」 | 往日志打一条字符串；官方明确「**无论是否勾选了该节点图**，逻辑成功运行时都会打印」 |
| **逻辑子图调试模式** | 在日志里**双击生效的节点图** | 看该时间点的**逻辑子图**（= 从某个事件节点触发的一次执行流）；**悬停节点即可读输入输出值** |

**三条实战要点**：

1. ⚠️ **日志要先"筛选节点图"**：日志页签里不勾选要观察的图，运行时**不会**返回「节点图事件」与引脚值 ——
   官方 FAQ 里专门有一条（`faq/mh3nb3rv8goe_试玩及调试.md`）。
2. ⭐ **实体 / 列表的值只能"悬停读"，打不出来**：平台**没有**通用的"实体转字符串"节点
   （节点索引里只有 `拼接列表` 与时间格式化）→ **打印只用来当标签**（如 `E:命中检测触发时`），
   要看"命中实体是谁"就进调试模式悬停那个引脚。
3. ⭐ **排查"某能力到底有没有"最快的路径**：把**所有候选事件**各接一个 `打印字符串`（内容 = 事件名），
   跑一次看哪个标签出现 —— 比逐个试快，也不会漏掉"两个事件都触发"的情况。

## 4. 输入与点击（常驻光标体系）

⭐ **要点：平台没有通用的"点击事件"** —— "点某个物体"这件事由**常驻光标**体系提供。
做任何"点击放置 / 点击交互"之前先读这一节。

### 4.1 配置入口

**玩家模板 → 玩家编辑 → 光标配置**：

| 配置项 | 说明 |
| --- | --- |
| 光标常驻 | ⚠️ **关闭时整个光标系统及相关功能无效**；开启则光标常驻显示 |
| 可点击层级 | 四个层级：**场景 / 受击盒 / 物件碰撞 / 光标碰撞** |
| 光标最多可选目标数 | 光标最多可同时选取的目标数量 |
| 点击可穿透UI控件 | 关闭时，光标点击穿过 UI 控件后**不再打到场景** |

### 4.2 相关节点

| 节点 | 作用 | 备注 |
| --- | --- | --- |
| 设置玩家光标是否常驻 | 运行时开关常驻显示 | |
| 设置玩家光标点击可选取目标 | 运行时设定**层级筛选 id** + 最多选取数量 | |
| 设置玩家光标是否穿透UI控件 | 运行时设定穿透 | |
| 激活/关闭光标碰撞盒 | 按**碰撞盒序号**开关某实体的点击碰撞 | **仅对物件生效**；序号可单独控制 → 适合"按格子开关可点击性" |
| 获取光标命中结果 | **轮询**取"本机持久光标"的**命中实体列表 / 位置列表 / 数量** | ⚠️ **仅超限模式可用** |
| 获取预瞄准的射线命中信息 | 取预瞄准的命中位置与**命中实体** | ⚠️ 仅超限模式可用 |

### 4.3 已知事实与坑（都会咬人）

- **"点击"在平台语义上就是「普通攻击键」**：官方 API 文档里 `KeyboardNormalAttackKeyDown` 的说明写的就是
  **鼠标左键**（`KeyboardSprintKeyDown` = 鼠标右键）→ 所以点击与**攻击 / 技能**体系天然纠缠，不只是一个 UI 事件。
- **移动端必须补一个状态效果**：官方原文 ——「在移动端使用常驻光标功能时，**必须要使用单位状态效果
  【光标点击释放技能】**来补充 PC 端鼠标点击选中的额外逻辑」（单位状态效果池里叫「光标点击施放技能」）。
  → 反过来说明 **PC 端的点击是"选中"语义**，且与技能挂钩。**跨平台时这条不能漏。**
- **客户端侧的点击**：`光标检测区域控件`（API 名 `CursorEventArea`）是**客户端控件**，可挂客户端脚本，
  是"可接收光标射线事件的区域"（配图片/文本框即成一个按钮）；键鼠/手柄按键走客户端 Lua 的
  `AddKeyEventListener(eventType, callback)`。
- **选项卡组件是"走近才能选"**：它赋予玩家对动态物件/造物的交互操作，但**触发靠角色进入触发区**
  （长方体 / 球体 / 胶囊体）→ **不适合隔着半张地图点格子**；它的「选项卡选中时」事件会给出**选项卡序号**，
  天生能区分"点的是哪一个"。

> ⚠️ **官方文档没写"点击之后向节点图发哪个事件"** —— 因为**平台不发事件**：
> 一份能用的第三方参考资产证明，点击要自己用「**检测体 + 范围查询 + 自定义信号**」造出来（见 §4.4）。

### 4.4 「点击某个实体」的实际交付方式（2026-10 实证）

**结论：点击是通过「信号」交付给节点图的**，而不是某个内置事件 —— 一份能用的第三方参考资产
（本地学习用、不入库）用的是这个接口：

```
监听信号（信号名 = 点击实体时）
   出参：事件源实体 / 事件源GUID / 信号来源实体 / ⭐ 被点击实体
        └→ 业务逻辑（例如读/写「被点击实体」自己的自定义变量）
```

两条可直接复用的经验：

1. **消费侧**：业务图从 `监听信号` 起手，出参取 **`被点击实体`** 就知道"点到了谁"。
   ⚠️ `监听信号` 只能监听**信号管理器里已定义的信号** → 该信号是**自定义的**，**平台不会替你发**。
2. **状态存哪**：把状态（是否选中 / 槽位号 / 占用）写成 **`被点击实体` 自己身上的自定义变量**
   （`设置自定义变量`，目标实体 = 被点击实体）—— 比在关卡图里维护一张实体↔槽位的映射表更省事，
   也与"实体销毁时用自定义变量快照读回"的技巧天然配套。

#### 生产侧：怎么把"点击"造出来（同一份资产的完整链路）

**平台没有点击事件，但有一个可复用的做法** —— 用一个**检测体实体**在点击点做一次**范围查询**。
完整链路是**五段**，前两段解决"点击点从哪来"：

```
① 客户端 → 服务器：发送信号 `鼠标点击`，参数 = 目标位置 / 目标旋转 / 事件源实体
     📌 平台惯例：**位置与旋转当信号参数传**（跨端无法直接传引用，只能这么传）
        ↓
② 服务器：监听信号(鼠标点击) → 创建元件(检测体, 位置 = 目标位置, 旋转 = 目标旋转, 拥有者 = 事件源实体)
        ↓
③ 检测体（实体创建时 → 自毁）
     ├→ 播放限时特效（缩放调小）                    ← 点击处视觉反馈
     ├→ 获取自身位置 → 圆心；取自身自定义变量（如「被选实体大小」）÷ 2 → 半径
     ├→ 获取场上指定类型实体（实体类型 = 物件）
     │     → 获取指定序号的实体列表 → 获取指定范围的实体列表（中心点, 半径）   ⭐ 候选 = 点击点附近的物件
     ├→ 列表迭代循环（迭代候选）
     │     └→ 读候选自己的自定义变量（如「是否属于实体」）→ 双分支 → 第一个合格的写入节点图变量「目标实体」→ 退出循环
     ├→ 获取节点图变量（目标实体）→ 【发送信号】（信号名 = 点击实体时，被点击实体 = 该实体）
     └→ 启动定时器（名称「销毁」）→ 定时器触发时 → 销毁实体（自身）
        ↓
④ 消费图：监听信号(点击实体时) → 切换被点实体自己的自定义变量（如「是否被选中」）
        ↓
⑤ 反馈图：`自定义变量变化时` → 加/减「单位状态」做高亮（见 §4.5）
```

**五条可复用的设计要点**：

| 要点 | 说明 |
| --- | --- |
| ⭐ **位置当信号参数传** | 客户端能拿到光标/瞄准的世界位置，但**不能直接给服务器引用** → 打包成**信号参数**（目标位置/目标旋转）发过去，服务器再用它 `创建元件` |
| **候选靠"标记变量"过滤** | 不是所有物件都能点 → 给可点实体挂一个自定义变量（如 `是否属于实体`），迭代时逐个判断 |
| **范围查询带类型过滤** | `获取场上指定类型实体`（实体类型 = **物件**）→ `获取指定范围的实体列表`（中心 + 半径） |
| **检测体自毁** | 定时器「销毁」+ `销毁实体(自身)` → 每次点击只留一瞬间，不会堆积实体 |
| **中间实体不改状态，只发信号** | 检测体只负责"把点击翻译成一个带实体的信号"，业务逻辑全在监听方 → **检测体可复用、业务可替换** |

> ⚠️ **唯一尚未见到的实现**：**谁发送 `鼠标点击` 这个信号**（客户端脚本 `ServerSignal:SendSignal`，
> 还是技能/客户端节点图）。这决定了"取光标世界位置"的具体写法 —— **换项目时要自己确认这一步**。

> 🚫 **合规提醒**：第三方资产**不要随作品发布**（搬运他人内容通常被平台规则禁止）——
> 只学做法、自己实现。

### 4.5 选中态与高亮（视觉反馈）—— 同一套资产的第三块

**点击只是输入，玩家还需要"看得出选中了"**。参考资产的做法是把**状态**变成**单位状态**：

```
自定义变量变化时（事件源实体 = 变量被改的那个实体）
 ├→ 是否相等（输入1 = 出参「变量名」；输入2 = 你要盯的变量名，如「是否被选中」）→ 双分支
 │     └ 不等（别的变量在变）→ 丢弃
 └→ 双分支（条件 = 出参「变化后值」）
       ├ 是 → 添加单位状态（施加者/施加目标 = 事件源实体；单位状态配置ID = ?；施加层数 1）
       └ 否 → 移除单位状态（移除目标 = 事件源实体；同一配置ID；移除方式 = 最快丢失叠加层的状态）
```

**两个可复用的平台要点**：

| 要点 | 说明 |
| --- | --- |
| ⭐ **`自定义变量变化时` 是个好用的事件** | 出参给 **变量名 / 变化前值 / 变化后值**，事件源实体 = 变量所属实体 → 可以拿它**驱动一切"状态→表现"的联动**（高亮、UI 刷新、音效…），不必在写状态的地方到处挂表现逻辑 |
| **高亮用「单位状态」实现** | `添加单位状态` / `移除单位状态` + 一个**单位状态配置ID**（截图里是 `1077936129`，属于**项目内的引用 id**，换个项目要换成自己的配置）。用状态做高亮的好处：**自动跟随实体、实体销毁时自动消失**，不用自己管理特效生命周期 |

> 📌 组合起来的完整链路（参考资产的三块拼图）：
> **① 检测体**（点击点 → 范围查询 → 发信号）→ **② 消费图**（监听信号 → 切换被点实体的 `是否被选中`）
> → **③ 反馈图**（`自定义变量变化时` → 加/减单位状态高亮）。
> 三块都拆得开、都能单独复用 —— 我们要的正是**②③**，①换成我们自己的槽位查询。

## 5. 合规约束

- 平台有专门的创作规则，明确禁止**外挂 / 私服类的辅助工具**（模拟用户操作、改变操作环境、**修改数据**），
  且**制作与发布**都被列为禁止行为 → 因此：
  - ✅ **只读分析**官方导出的存档文件可以；
  - 🚫 **做能写回的工具并发布**不行（发布行为本身即违规）；
  - 🚫 官方文档正文、官方规则原文、他人分享的资产 **只在本机用于学习**，不进公开仓库、不转发。
- 详细条款摘录与判定结论保存在**配套的游戏侧工作区**（`rules/`），**不随本仓库公开**。
- ⚠️ 官方保留**随时修订**规则的权利 → 所以本平台目录里带了一个复核工具（见下）。
