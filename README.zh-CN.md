# 基座 —— 做并发布一个关卡 / 小游戏的通用底盘

[English](README.md) ｜ **中文**

> 🤖 **AI 助手：先读 [`AGENTS.md`](AGENTS.md)** —— 里面是语言约定、分层约定、合规姿态、
> 单一实现原则等本仓库要求遵守的东西。

## 这是什么

一套**基座**，装的是「**从零做到发布**」这件事里可以沉淀下来的三层东西：

| 层 | 内容 | 换平台时 |
| --- | --- | --- |
| **抽象层**（`design/`） | `balance-model.md`（数值的**唯一来源**）、`architecture.md`（分层架构）、`map-template.md`（关卡设计模板） | **不动** |
| **平台适配层**（`platforms/<平台>/`） | 每个目标平台一份：能力 / **硬限** / 事件模型 / 合规约束 / **该平台专属工具** | **只改这层** |
| **通用工具**（`tools/`） | 检查文档镜像是否落后上游、解析 PAC 给 git/curl 兜底、证明一次提交**只改了注释** | 不动 |
| **方法规范**（`AGENTS.md`） | 合规姿态、「**实测优先于文档**」、单一实现、记录规范、AI 使用边界 | 不动 |

**平台工具放基座是对的** —— 它们按平台目录隔离，不会互相污染；而**数据与结论留在游戏侧**
（路径由参数给出）。当前已适配：**千星奇域**；Steam / iOS / Android 有各自的待填清单。

具体游戏放在**它自己的目录 / 仓库**里，用**显式路径**（`--docs`、`--mirror`、`--rules-dir`）调用这里的工具。
基座里**不放**任何游戏内容、第三方内容与个人信息。

## 设计层的规矩

- `design/` 下的一切必须**以「平台无关」的方式表达**：**抽象本身**不能建立在某个引擎的特性上；
  允许保留**一个贯穿的实例**（本项目用的具体平台）作为说明，但**必须标成实例** ——
  把实例那段删掉，文档仍应自洽。换平台时改的是实例，不是抽象。
- 数值与结构改这里，平台实现改游戏仓库 —— **同一个决定绝不写两份**。
- `architecture.md` 保留那些「换了平台也成立」的抽象 —— 例如把玩家与 AI 统一成一个
  **指令流接口**，使单机 AI、真人玩家、联机对战共用同一套架构。

**关于本仓库里没有的路径。** 设计文档会引用 `rules/compliance.md`、`design/<某个具体关卡>.md`、
`research/<某个平台>.md` 这类文件 —— 它们在**配套的游戏侧工作区**里，**不随基座公开**。
把它们当作"这个抽象当初是在什么上下文里定的"的线索即可，不必去找得到。

## 工具

| 脚本 | 作用 | 用法 | 退出码 |
| --- | --- | --- | --- |
| `tools/check_docs_update.py` | 判断本地文档镜像是否落后于它的上游仓库（上游仓库由参数或镜像自带的状态文件给出） | `--mirror <镜像根>`、`--repo owner/name`、`--record`、`--json` | 0=一致 / 1=有更新或无基线 / 2=连不上 |
| `tools/pac_proxy.py` | 解析 PAC（本机以十进制字节返回，需解码）供 git/curl 使用 | `--git-config` | 0 |
| `tools/verify_comments_only.py` | 证明一次提交**只动了注释**（剥掉注释后逐字节比对） | 在目标仓库内运行 | 1 = 代码也变了 |

除 `--record`（写基线状态）外，全部**只读**。

## 用之前值得知道的约定

- **注释、文档、提交信息都用中文**（读者是作者与 AI 助手）；**只有两份 README 是双语的，必须一起改**。
- **单一实现**：能力一旦落进正式工具，**探索期的临时脚本立刻删除** —— 两份实现迟早漂移，
  而且被遗忘的那份很难发现。
- **合规优先**：分析导出文件没问题，但**绝不做能写回游戏数据的工具并发布**；
  官方文档正文、官方规则原文、他人分享的资产**只留本地**，公开的只有**自己推导出的结论**。
